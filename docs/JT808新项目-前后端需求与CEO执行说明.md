# JT808 电池防盗项目：前后端需求与 CEO 执行说明

> 此文档可直接交给新项目的 CEO Agent。目标是在本机从需求出发交付可运行的前后端系统，并用自动化测试和实际数据库联调验证。执行范围和验收结果以实际证据为准。

## 1. 用户决定与实施边界

1. 这是一个重新开始的新项目。**不读取、搜索、复制、对比或分析 demo1 的任何代码，也不依据其代码推断实现。**以本需求、用户提供的协议正文和现有数据库结构为依据。
2. 采用用户已确认的《标准版808协议（简化版）-v3.4-20251126 (1).docx》实际正文、字段定义和报文规则；以本次提供文件的正文为准；不得假设它与此前其他文件内容一致。
3. 前端使用 Vue 3 + Vite，满足基本功能、清晰易用即可。后端使用 Java、Spring Boot、Netty、MyBatis-Plus 和 Oracle。建议 Java 17、Maven、Spring Boot 3；依赖具体版本由后端核对兼容性后固定。
4. **允许连接和操作指定的本地数据库**：可以检查元数据及现有表，允许为实现和验证需求执行必要的查询、新增和更新，并在隔离的测试数据范围内进行必要的数据操作。不要重复建表；沿用现有表、序列及触发器。此前的禁止建表、改表、删除数据库对象、清库和破坏既有业务数据的约束继续有效。若发现表结构不足，先实现不依赖结构变更的部分并报告，不能自行执行 DDL。
5. CEO 先形成简洁计划并分派任务，然后推进实现和测试，不要为普通开发、文档或测试逐项设置人工审批。能并行进行的工作并行开展。
6. 供新项目 Agent 使用的需求、协议、数据库参考和使用说明放在本项目 `docs`；JT808 说明文档另同步到 `D:\Java__\work\note\jt808`。新项目代码目录由实际 Paperclip Project Codebase 配置决定，不能默认覆盖旧项目目录。

## 2. 项目目标

实现 JT/T 808 终端接入与电池位移防盗：终端经 TCP 接入平台，平台按协议解析并应答，保存设备和位置数据，基于有效位置判断设备是否偏离报警参考点，并在前端展示设备、位置、轨迹与报警。

系统至少能够本机启动、接收模拟终端报文、将测试数据写入已有 Oracle 表、通过 HTTP API 查询，并在前端完成基本查看。最终交付包括源码、启动说明、配置说明、模拟报文方法和测试报告。

## 3. 输入资料与优先级

- 协议：用户提供的《标准版808协议（简化版）-v3.4-20251126 (1).docx》。协议正文是消息和字段实现依据。
- 数据库：用户提供的 `schema-oracle.sql` 仅作为现有结构参考，不作为需要执行的建表脚本。连接数据库后以实际表、字段、主键、索引、序列和触发器元数据为准，先检查后映射。
- 本需求说明与用户后续明确指示：确定功能、技术选择、执行权限和交付边界。
- 协议缺失或含糊时：需求/API Agent 写明原文依据、假设和影响，先实现不受影响的功能；不能伪称已确认，也不因非关键细节暂停整个项目。

## 4. 数据库与配置

- 类型：本机 Oracle 11g XE。
- JDBC URL：`jdbc:oracle:thin:@127.0.0.1:1521:XE`。
- 用户名：`SYSTEM`，本次用户提供用于本地开发联调。这个账号权限较高；开发代码不得包含 DDL 或破坏性维护操作。若后续提供专用低权限应用账号，应支持通过配置切换。
- 密码：从 `GPS_DB_PASSWORD` 环境变量或 Paperclip Secret 读取，不放源码、文档、任务评论、测试输出、命令历史或日志。当前 Windows 用户环境此前已登记该变量，但 Paperclip 运行进程是否继承必须由实际运行检查；服务以其他账号启动时需单独配置。
- 建议变量：`GPS_DB_URL`、`GPS_DB_USER`、`GPS_DB_PASSWORD`、`GPS_DB_MAX_POOL_SIZE`；URL、用户名、连接池大小可提供本机默认配置，密码不得提供明文默认值。连接池上限初始建议 5。
- 现有对象参考：`GPS_DEVICE`、`GPS_LOCATION`、`GPS_ALARM`，以及位置/报警 ID 对应的现有序列和触发器。以实际元数据为准，避免重复创建或假设对象一定存在。
- 允许应用完成业务必须的 INSERT、SELECT、UPDATE。测试使用专用测试终端号、可识别的测试数据及限定范围；禁止批量清理、覆盖或删除其他业务数据。若测试确需删除自己创建的数据，只允许精确限定到可核实的测试记录，不能执行清表。
- Oracle 11g 的分页、数据类型、时间字段及 ID 生成方式必须实际兼容；配置 MyBatis-Plus 时不得与已有序列/触发器重复生成或覆盖主键。禁止自动 DDL、自动 schema 初始化和数据库迁移。

## 5. 后端基本需求

### 5.1 终端接入与协议

1. Netty TCP 服务接收终端连接；监听地址、端口、空闲超时和最大帧缓存可配置。默认 TCP 端口可用 `7611`，端口冲突时通过配置调整。
2. 实现协议正文覆盖本项目所需的帧边界、转义与反转义、校验、消息头、BCD/编码、字段字节序与单位转换，并能记录不含凭据的错误信息。
3. 实现正文允许且业务需要的注册、鉴权、心跳、位置上报和平台应答；参数读取/下发按正文和可核实规则实现。未定义的细节列为限制，不要自行捏造协议值。
4. 异常或不完整报文应安全拒绝或按协议处理，不得因无效定位、错误帧或校验失败生成位移报警。
5. 提供模拟终端或报文样例和操作说明，能够在本机演示接入、上报与应答。

### 5.2 设备、位置与报警

- 将可识别设备映射到已有设备表，展示在线状态及最后在线时间；连接与断开状态按实现的实际能力维护。
- 将有效位置映射到已有位置表，保留协议要求的设备时间、坐标及适用的原始信息；明确坐标单位和方向。
- 按现有表可支持的方式设置和维护报警参考点；协议没有明确规定时，需求/API Agent 先制定可运行的默认策略并记录。不得凭空修改数据库结构；如无法持久保存参考点，要报告限制并继续可做部分。
- 对有效位置计算到参考点的距离，**严格大于 200 米**时生成位移报警；阈值可配置。等于或小于阈值不生成该报警。去重、防抖或冷却必须明确说明，不能悄悄改变阈值语义。
- 设备、轨迹、报警数据使用 MyBatis-Plus 映射到既有表；需要复杂 Oracle 11g SQL 时可使用必要的自定义 Mapper，SQL 必须与现有结构兼容。

### 5.3 HTTP API

默认 HTTP 端口 `8080`，可配置。需求/API Agent 根据前端需要形成并维护接口契约，至少包括：

- 查询设备列表及设备详情。
- 查询设备最新位置与按时间范围分页查询轨迹。
- 分页查询报警列表及报警详情，可按设备和时间筛选。
- 按可实现的参考点方案提供必要的查询/设置能力；无法安全实现时在契约中说明。
- 统一约定请求、响应、分页、时间格式、字段单位、错误码、空值及接口示例；提供 mock 数据供前端并行开发。

API 文档应列出真实实现的 URL 和示例，不要把规划接口标成已交付。认证和敏感信息处理方案根据实际使用场景说明；本地演示默认值不代表生产安全方案。

## 6. 前端基本需求

采用 Vue 3 + Vite；可使用 TypeScript 和成熟组件库，界面以功能清晰为主，不要求复杂设计。最少提供：

1. 设备列表：终端号、在线状态、最后在线时间；支持基本搜索、刷新和分页。
2. 设备详情：设备基础信息、最新位置，以及进入轨迹和报警列表的入口。
3. 轨迹查询：按设备和时间范围显示位置记录、时间与坐标，支持分页或有限条数查询。**地图不是启动前置条件**；若没有地图服务或密钥，列表和坐标即可交付，地图可作为后续增强。
4. 报警列表：显示设备、报警类型、时间、距离和状态信息，支持基本筛选与详情。
5. 页面提供加载中、空数据、接口失败及可理解的错误提示；通过可配置 API 地址连接后端，本地开发可通过代理解决跨域。
6. 提供可复现的安装、启动、构建命令及入口地址；先用 mock 开发，再与实际后端联调，最终明确哪些页面已连接真实 API。

7. CEO 最终给出：源码绝对路径、分支或提交、前后端启动与构建命令、数据库配置变量名、模拟终端方法、功能完成情况、自动测试和实际数据库联调结果、未解决问题。Agent 运行成功或任务显示 Done 不等同于项目验收完成。

## 9. 避免重复踩坑

- **只读或命令被策略拦截**：Paperclip Agent 权限、项目 Codebase、文件 MCP、实际 sandbox 和 Windows 权限是不同层。每位 Agent 在真实运行中验证写入和命令；失败记录实际命令、路径和完整错误，交 CEO 修运行配置，不要一遍遍生成等待任务。项目范围读写已获用户授权；根据运行环境配置生效，不假定聊天授权能覆盖系统策略。
- **PowerShell 启动错误**：先识别是启动策略、执行器还是权限；若已验证可用，可使用其他已获允许运行方式。不要把不同错误都归因于工作区只读。
- **Paperclip API 不通或 Agent 名单不可见**：在 Agent 的实际环境测试；主机能访问 localhost 不代表沙箱可访问。优先使用已验证的 Paperclip 协调 MCP，并核查名单、任务读取与回写；旧项目的本地桥接/补丁不保证新项目和升级后可用。不要无依据地改端口。
- **MCP 审批策略冲突**：预检中检查目标工具是否可被无人值守调用。出现 approval policy 冲突时报告工具和策略，按实际授权修复；不要通过关闭全部安全控制掩盖问题。
- **预算未到额度仍 hard stop**：检查是否存在未定价或等待记账的运行、暂停原因和提供商连接；调整金额不一定解决待记账问题。不要伪造费用或反复重试；可继续安排其他可用 Agent。不得擅自关闭预算保护。
- **任务依赖与恢复循环**：仅为真正必需的产物设置 Blocked by。CEO 协调任务保持可运行；同一原因失败两次就停止自动重试并汇报明确阻塞、责任人和下一步，不递归创建确认任务。一次性工作不强制配置 Monitor。
- **人工审核过多**：测试 Agent 可自动检查一般实现和文档并保留证据。需求中的小缺口先采用明确标注的合理默认值继续开发。凭据轮换及正式发布等确实需要授权或实际人操作的事项，单列待办，不得阻塞与其无关的实现；不得虚构独立审核或已轮换。
- **运行成功但没有代码**：每次交付报告列文件、代码位置、构建和测试输出；缺少交付物时不得标为项目完成。
- **凭据泄露和日志**：密码只走环境变量或 Secret，不进入代码与文档。用户提供的现有密码此前已出现在聊天中，登记环境变量不等于轮换；由有权限的人在合适时机轮换并更新 Secret。安全待办与不受影响的开发并行推进。
- **前端缺席或无报告**：前端单独建任务与负责人，从 mock 并行开发；最终明确前端目录、入口、启动命令和联调证据。
